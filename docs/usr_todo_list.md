## 深度图频率与网络结构设计方案

### 方案零（优先级最高）：10Hz 深度图 + 简单 CNN + depth_age 拼接
- **原理**：保持 10Hz 完整点云转换深度图，通过简单 CNN 提取特征后拼接 depth_age 标志位
- **深度图频率**：10Hz（完整扫描，约 12000 点）
- **有效像素比例**：60~80%（高质量深度图）
- **网络结构**：
  ```
  深度图 (180×32) → CNN → 特征向量 (512维)
  本体感知 → MLP → 特征向量 (256维)
  depth_age → 标量 (1维)
  ─────────────────────────────────────
  拼接 → MLP → 动作输出
  ```
- **关键设计**：每帧都用最新的本体感知和 depth_age，但深度图可能重复（10Hz vs 50Hz）
- **优势**：深度图质量高，网络结构简单（无需时序模块），训练稳定，实现简单
- **劣势**：无法利用历史深度图信息进行预测，依赖 depth_age 标志辅助决策
- **适用场景**：室内外环境，追求深度图质量同时保持网络简洁

### 方案一：50Hz 深度图（已验证不可行，废弃）
- **原理**：将 Mid360 点云发布频率从 10Hz 提升到 50Hz，每帧点云数量约为原来的 1/5（约 4000 点）
- **验证结果**：经过数据采集验证，50Hz 输出的点云范围变窄，转换后的深度图最多只有三分之一的有效范围
- **问题分析**：由于频率过高，雷达线束扫描区域无法实现全域覆盖，按照上中下的顺序来回切换有效范围，导致有效特征稀疏
- **有效像素比例**：实际仅约 10~20%（10Hz 为 60~80%），且分布不均匀
- **结论**：不考虑该方案，深度图信息损失过大，无法支持 policy 稳健运动

### 方案二：10Hz 深度图 + 时序网络
- **原理**：保持 10Hz 完整点云，通过时序网络处理多速率输入
- **时序网络**：推荐 GRU（平衡性能和计算量），或 ConvLSTM（结合 CNN+LSTM）
- **混合输入**：深度图（10Hz）+ 本体感知（50Hz）+ depth-img-age 标志
- **网络结构**：CNN 特征提取 + GRU 时序融合 + MLP 决策
- **优势**：深度图质量高，可利用历史信息预测，更接近真实机器人
- **劣势**：实现复杂，需自定义 ActorCritic 网络，可能需要修改 OnPolicyRunner
- **适用场景**：复杂动态环境，追求最优性能

### 过渡方案（推荐）
- 先以方案一训练，同时输入 depth_age 标志
- 为后续升级到方案二做准备
- 即使将来切换到 10Hz，depth_age 逻辑已经就绪
