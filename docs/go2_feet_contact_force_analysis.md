# Go2 足端接触力惩罚（feet_contact_force）物理建模分析

## 当前参数

```python
feet_contact_force = RewTerm(
    func=mdp.contact_forces,
    weight=-0.08,
    params={"sensor_cfg": SceneEntityCfg("contact_forces", body_names=".*_foot"), "threshold": 100.0},
)
```

`threshold=100 N`：足端接触力超过 100N 的部分，每 1N 扣除 0.08 奖励。

## 问题

该设定导致策略“轻手轻脚”——支撑相触地力度不足。对于简单的 `go2_loco_skill_walk_cfg.py`（无外载），这不是致命问题；但对于 `go2_loco_skill_walk_mid360_depth_10hz_cfg.py` 的 Stage1，策略学到的“省力步态”在 Stage2 面对额外 2.6kg 负载（Orin NX + Mid360 + 安装座）时，地面反力不足以高效支撑身体，可能导致跟踪精度下降或步态塌缩。

---

## Go2 足端受力物理建模

### 静态受力

| 配置 | 总质量 | 总重量 | Trot 步态单足静态载荷（2 足支撑） |
|------|--------|--------|----------------------------------|
| 简单 Go2（Stage1） | ~15.0 kg | ~147 N | **~73.5 N** |
| Mid360 满配（Stage2 max） | ~17.6 kg | ~173 N | **~86.5 N** |

### 动态受力（Trot 步态，0.5–1.0 m/s）

四足机器人 trot 步态的足端垂直地面反力（GRF）峰值通常是静态载荷的 **1.5–2.5 倍**，加上水平方向分量（约占垂直的 0.2–0.4），合力进一步增大：

| 配置 | 单足静态载荷 | 典型动态峰值（2.0×） | 剧烈动态峰值（2.5×） |
|------|-------------|---------------------|---------------------|
| 简单 Go2 | 73.5 N | **~147 N** | ~184 N |
| Mid360 满配 | 86.5 N | **~173 N** | ~216 N |

---

## 核心问题：threshold=100N 过于严苛

```
threshold = 100 N → 低于两种配置的典型动态峰值
```

这意味着：

- 即使是正常行走（非粗暴动作），足端力也会**持续触发惩罚**
- 该惩罚实际上退化为“最小化所有足端接触力”，而不仅仅是“抑制过度冲击”
- 策略被激励用更轻的触地、更短的支撑相来压低接触力 → 表现为“轻手轻脚”

**数值示例**：简单 Go2 正常 trot 的单足峰值约 147N，超 threshold 47N，每步惩罚 = 47 × 0.08 = **3.76**。而任务奖励（`track_lin_vel_xy_exp` 三项合计）最高约 3.0。单步足端力惩罚就已压倒全部任务奖励，策略必然扭曲。

---

## 推荐修改方案

核心原则：**threshold 应设在正常动态范围之上，仅在冲击过大时激活；weight 应降低到不主导总奖励的程度。**

### 方案 A（推荐）：适度调整

| 参数 | 当前值 | 建议值 | 变化 |
|------|--------|--------|------|
| `threshold` | 100 N | **180 N** | +80% |
| `weight` | -0.08 | **-0.04** | -50% |

**物理含义**：
- 180N 约等于简单 Go2 的 2.45× 动态峰值，Mid360 满配的 2.1× 动态峰值
- 正常行走（≤180N）不受惩罚；只有粗暴踩踏、高处跳落等极端情况才触发
- 惩罚减半后，即使触发也不会压倒任务奖励

**数值验证**：

| 场景 | 单足峰值力 | 旧惩罚 | 新惩罚 |
|------|-----------|--------|--------|
| 正常 trot（Mid360 满配，~170N） | ≤ threshold | (170-100)×0.08 = **5.6** | 低于阈值 = **0** |
| 较猛触地 | ~220 N | (220-100)×0.08 = **9.6** | (220-180)×0.04 = **1.6** |
| 高处跳落冲击 | ~350 N | (350-100)×0.08 = **20.0** | (350-180)×0.04 = **6.8** |

旧方案下一次正常 trot 就扣除 5.6，远超任务奖励总和（~3.0）；新方案下正常行走完全不受罚，极端冲击的惩罚也控制在合理范围。

### 方案 B（保守调整）

| 参数 | 当前值 | 建议值 | 变化 |
|------|--------|--------|------|
| `threshold` | 100 N | **150 N** | +50% |
| `weight` | -0.08 | **-0.05** | -37.5% |

阈值仅提升到 2.0× 简单 Go2 静态载荷，保留了对较强触地的约束。适用于希望更稳健、不急于完全放开足端力限制的场景。

---

## 结论

**推荐方案 A**（`threshold=180N`, `weight=-0.04`），理由：

1. **物理上正确**：180N 恰好覆盖两种配置的正常动态范围，语义从“压制一切接触力”回归到“抑制过度冲击”
2. **训练上兼容**：Stage1 策略不再被迫“轻手轻脚”，学到的步态力度自然兼容 Stage2 的重载
3. **量级合理**：惩罚减半后，即使在极端冲击场景，惩罚量级也不会超过任务奖励的数倍，避免策略扭曲
4. **正则化仍然有效**：与 `feet_contact_force` 同类的 `feet_slide`（-0.15）、`feet_stumble`（-0.5）仍保留较强约束，足端行为的整体正则化不会失控
