# Go2-Loco-Skill-Walk-Mid360Depth-10Hz 学生 Stage4 网络设计优势分析

> **日期**: 2026-08-09
> **适用环境**: Go2-Loco-Skill-Walk-Mid360Depth-10Hz（base 版本，非 GRU）
> **背景**: 补上 `depth_image_age` 后，学生 Stage4 重训地形可达等级收敛于 4.7 左右；教师 Stage3 收敛于 5.3 左右（上限有效值 5.0，超出部分为边缘拓展的平坦地形）。学生使用的深度特征提取网络结构简单、参数量小，但收敛快、效果尚可。本文总结其关键设计优势。

---

## 一、结论

base 学生网络效果好，**不是因为"结构简单"，而是因为它把正确的归纳偏置、富信息的特征压缩、直接的梯度路径和预条件化的输入空间组合在了一起**。小参数量是这些设计的结果，而不是原因。

可训练总参数量约 **0.47M**：

| 组件 | 参数量 |
|------|--------|
| `DepthImageEncoder`（深度 CNN） | 57.1K |
| Student MLP（475→512→256→128→12） | 409.5K |
| 可训练总计 | ~0.47M |

---

## 二、关键设计优势（按重要性排序）

### 1. 与传感器几何对齐的"轴分解卷积" + 方位循环 padding

`rsl_rl/networks/depth_image_encoder.py`：

```python
self.horizontal_conv = nn.Conv2d(1, 16, kernel_size=(1, 3))   # 只沿方位角卷积
self.vertical_conv   = nn.Conv2d(16, 32, kernel_size=(3, 1))  # 只沿俯仰角卷积
# forward: torch.cat([x[..., -1:], x, x[..., :1]], dim=-1)    # 方位环绕
```

- Mid360 深度图是 180(方位) × 32(俯仰) 的球面投影：**方位角是闭环、俯仰角有局部结构**，分解卷积就是该几何先验的硬编码；
- 方位循环 padding 让卷积核跨过 0°/360° 接缝，全景图左右边缘不断裂——普通 2D 卷积（零填充）不具备此先验；
- **权重共享的等效容量远大于参数量**：同一组核在 180 个方位列共享，水平卷积仅 64 参数，却等效覆盖整圈 360°。

### 2. avg + max + min 三统计池化 → 192 维紧凑富特征

```python
avg_feat = self.avg_pool(x).flatten(1)
max_feat = self.max_pool(x).flatten(1)
min_feat = -self.max_pool(-x).flatten(1)   # 64×3 = 192 维
```

- 空间压缩由池化**免费**完成，CNN 无需花费参数学习"8×45 → 向量"；
- 三种统计量互补（均值=整体地形分布、最大=最远开阔方向、最小=最近阻挡），下游 MLP 获得 192 个冗余但各有侧重的特征；
- 对行为克隆而言冗余是优点：梯度可经多个统计通路回传，CNN 不依赖单一路径存活。

### 3. 无瓶颈直连：475 维输入直接进 [512,256,128] MLP

学生观测 = 282（本体 6 帧全量）+ 1（`depth_image_age`）+ 192（深度特征）。

- 深度特征**不经过任何窄瓶颈**（对比 GRU 方案的 32 维 latent），像素→动作仅 CNN → MLP 两跳，BC 梯度几乎无衰减直达 CNN；
- 6 帧本体历史为 MLP 提供隐式时序上下文（关节轨迹、动作历史），部分补偿 10Hz 深度图的陈旧性。

### 4. 观测空间的"预条件化"：env 侧预处理 + 关闭 running normalization

`go2_loco_skill_walk_mid360_depth_10hz_cfg.py` 中每个观测项均在进网络前完成 scale/clip；深度图额外做 `log_k=10` 对数压缩 + `fill_invalid` 填充；蒸馏配置设 `*_obs_normalization=False`。

- 所有输入从第 0 步起**有界、静态、良态**（深度 [0,2.5]、age [0,4]、本体各项 ±几），Adam lr=1e-3 开箱即用；
- 蒸馏阶段无 running normalizer 预热期、无教师/学生统计不一致问题——"训练开始后很快收敛稳定"的直接原因之一；
- log 压缩把近处（控制最相关）距离映射到更大动态范围，相当于把领域知识直接做进输入。

### 5. 端到端行为克隆 + 冻结教师：单一静止目标

`rsl_rl/algorithms/distillation.py` 仅 `MSE(student_act, teacher_act)`：

- 教师冻结 → 目标分布静止 → 纯回归问题，收敛快，无 RL bootstrap / 熵调参；
- 特征只按"动作相关性"塑造，CNN 无需重建或预测无用信息，无辅助损失系数（α/β）要调。

### 6. 规模匹配（0.47M 参数 vs 数据量）

- 数据规模 4096 envs × 60 步/轮；目标是"10Hz 深度 + 本体 → 教师动作"的平滑映射，0.47M 参数足够；
- v0.1.5 教训：增大 CNN 后地形等级反降至 3.0–3.5，证明**多余容量只会过拟合仿真噪声**；
- "强偏置 + 富池化 + 直连"优于"大容量 + 通用结构"。

---

## 三、为什么收敛快

静止回归目标 + 良态有界输入 + 小模型 + 192 维高信息特征 = 低样本复杂度。每轮更新 2 epoch × 60 步 × 4096 envs ≈ 24.6 万条独立转移，模型仅 0.47M 参数，可学映射很快被吃透。

---

## 四、剩余差距（4.7 vs 教师 5.0）的性质

不是容量问题，而是**单帧感知的结构性上限**：

- 深度图 10Hz、最大 2.5m：1.0 m/s 前进仅 2.5s 预瞄，地形切换反应窗口短；
- 帧间 100ms 陈旧：只能靠标量 age 提示陈旧度，无法利用多帧信息（无运动视差、无跨帧特征跟踪）；
- 深度图含机器人自身肢体/负载的自遮挡像素（raycast target 含腿和 loader），属额外噪声；
- 学生本体感知加噪（`enable_corruption=True`），教师则看到 50Hz 特权高度扫描 + 真实状态。

4.7 说明学生已基本榨干"单帧 10Hz 深度"的信息，再往上需要**时序/多帧信息**。

### 下一步低风险建议

1. **共享权重的双帧拼接**：同一 `DepthImageEncoder` 处理最近两帧（含各自 age），特征 192+192 进 MLP（CNN 参数不变，MLP 首层仅多 192 维），验证"多帧上下文"能否吃掉剩余 0.3 差距；
2. 若仍不足，再考虑方案B（GRU 完整实现：修好取帧逻辑 + `gradient_length≥10` + 特征对齐损失）。

---

## 五、与 GRU 方案的对照

GRU 方案失败的教训恰好印证以上优势：

| 关键优势 | base 方案 | GRU 方案（旧实现） |
|----------|-----------|--------------------|
| 特征路径 | 192 维富池化直连 MLP | 32 维瓶颈 + 多层 MLP + GRU |
| 时序输入 | 6 帧本体历史（隐式） | 取帧 bug 导致 `prop_latest` 错位 |
| 监督信号 | 单一 BC 目标，梯度直达 | latent 无监督目标（未实现特征对齐） |

时序建模本身没有错，错在旧实现丢掉了"正确偏置 + 直接梯度"这两个 base 方案真正值钱的东西。
