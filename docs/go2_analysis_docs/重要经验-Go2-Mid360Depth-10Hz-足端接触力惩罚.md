# 重要经验：Go2 足端接触力惩罚参数必须与物理量级对齐

> **日期**: 2026-08-09（重塑自 2026-07-25 的 `go2_feet_contact_force_analysis.md`）
> **适用对象**: `go2_loco_skill_walk_cfg.py`、`go2_loco_skill_walk_mid360_depth_10hz_cfg.py` 的 `feet_contact_force` 奖励项
> **一句话结论**: 惩罚项（尤其是力/力矩类）的 `threshold` 与 `weight` 必须对照物理量级设定——`threshold` 应高于正常动态范围、只在异常冲击时激活；`weight` 应保证单步惩罚远小于任务奖励。当前 `threshold=100N` 低于正常 trot 动态峰值（~147–173N），惩罚量级甚至超过任务奖励，策略被激励出"轻手轻脚"的省力步态，进而损害跨阶段迁移。

---

## 一、现象

Stage1 训练出的策略触地力度不足（"轻手轻脚"）：支撑相足端反力偏小、触地时间偏短。对无外载的简单 Go2 影响不大，但在 Stage2 面对额外 ~2.6kg 负载（Orin NX + Mid360 + 安装座）时，地面反力不足以高效支撑身体，出现跟踪精度下降或步态塌缩风险。

---

## 二、根因：惩罚参数与物理量级失衡

### 当前参数

```python
feet_contact_force = RewTerm(
    func=mdp.contact_forces,
    weight=-0.08,
    params={"sensor_cfg": SceneEntityCfg("contact_forces", body_names=".*_foot"), "threshold": 100.0},
)
```

`threshold=100N`：足端接触力超过 100N 的部分，每 1N 扣 0.08 奖励。

> 注意：mid360 环境 Stage2/3/4（`_restore_mid360_config`）实际使用更严格的 **`weight=-0.16, threshold=120N`**，量级失衡问题在重载阶段更严重。

### 静态受力

| 配置 | 总质量 | 总重量 | Trot 步态单足静态载荷（2 足支撑） |
|------|--------|--------|----------------------------------|
| 简单 Go2（Stage1） | ~15.0 kg | ~147 N | **~73.5 N** |
| Mid360 满配（Stage2 max） | ~17.6 kg | ~173 N | **~86.5 N** |

### 动态受力（Trot 步态，0.5–1.0 m/s）

四足 trot 步态足端垂直地面反力峰值通常为静态载荷的 1.5–2.5 倍，加上水平分量（约占垂直的 0.2–0.4），合力进一步增大：

| 配置 | 单足静态载荷 | 典型动态峰值（2.0×） | 剧烈动态峰值（2.5×） |
|------|-------------|---------------------|---------------------|
| 简单 Go2 | 73.5 N | **~147 N** | ~184 N |
| Mid360 满配 | 86.5 N | **~173 N** | ~216 N |

### 失衡的后果

`threshold=100N` 低于两种配置的典型动态峰值，意味着：

- 正常行走也持续触发惩罚 → 惩罚退化为"最小化所有足端接触力"，而非"抑制过度冲击"；
- 策略被激励用更轻触地、更短支撑相压低接触力 → "轻手轻脚"。

**数值示例**：简单 Go2 正常 trot 单足峰值约 147N，超阈值 47N，单步惩罚 = 47 × 0.08 = **3.76**；而任务奖励（`track_lin_vel_xy_exp` 三项合计）最高约 3.0。单步足端惩罚就压倒全部任务奖励，策略必然扭曲。

---

## 三、可复用经验（核心原则）

1. **惩罚阈值必须高于正常动态范围**：`threshold` 语义是"超过某强度才惩罚"，应标定在正常动作峰值之上（如 2.0–2.5× 静态载荷），只在粗暴踩踏、高处跳落等异常时激活；
2. **惩罚量级不能主导总奖励**：单步最坏惩罚应远小于（至少不超过）任务奖励总和，否则策略优化目标被惩罚项劫持；
3. **参数要与物理量纲对齐**：力（N）、力矩（N·m）类惩罚必须先用物理模型估算量级（静态载荷、动态峰值），再定 `threshold/weight`，不能凭经验拍脑袋；
4. **跨阶段迁移要考虑负载差异**：Stage1 无载学到的步态力度要能在 Stage2 重载下成立——若 Stage1 惩罚过严导致"省力步态"，重载后必然失效；轻载阶段训练的惩罚约束应比目标部署配置更宽松或至少等价；
5. **同类正则项分工明确**：足端行为已有 `feet_slide`、`feet_stumble` 等强约束，接触力惩罚应专注"抑制冲击"，不必承担全部步态塑形职责。

---

## 四、修改建议

### 方案 A（推荐）：适度放宽

| 参数 | 当前值 | 建议值 | 变化 |
|------|--------|--------|------|
| `threshold` | 100 N | **180 N** | +80% |
| `weight` | -0.08 | **-0.04** | -50% |

物理含义：180N ≈ 简单 Go2 的 2.45× 动态峰值、Mid360 满配的 2.1× 动态峰值；正常行走不受罚，仅极端冲击触发。

**数值验证**：

| 场景 | 单足峰值力 | 旧惩罚 | 新惩罚 |
|------|-----------|--------|--------|
| 正常 trot（Mid360 满配，~170N） | ≤ threshold | (170-100)×0.08 = **5.6** | 低于阈值 = **0** |
| 较猛触地 | ~220 N | (220-100)×0.08 = **9.6** | (220-180)×0.04 = **1.6** |
| 高处跳落冲击 | ~350 N | (350-100)×0.08 = **20.0** | (350-180)×0.04 = **6.8** |

### 方案 B（保守调整）

| 参数 | 当前值 | 建议值 | 变化 |
|------|--------|--------|------|
| `threshold` | 100 N | **150 N** | +50% |
| `weight` | -0.08 | **-0.05** | -37.5% |

阈值提升到约 2.0× 简单 Go2 静态载荷，保留对较强触地的约束，适用于希望更稳健的场景。

### 对 Stage2+ 的补充说明

若采纳方案 A 的思路，`_restore_mid360_config` 中的 Stage2/3/4 参数（当前 `-0.16/120N`）也应同步放宽（例如 `-0.08/180N`），否则重载阶段仍会重现"轻手轻脚"。

---

## 五、验证建议

- 训练中监控足端接触力统计（均值/峰值分布），确认正常步态下惩罚触发率接近 0；
- 对比 Stage1→Stage2 过渡期 reward 曲线与成功率，确认无断崖式退化；
- 若担心放开后步态变"粗暴"，保留 `feet_slide`/`feet_stumble` 的强约束作为兜底。
