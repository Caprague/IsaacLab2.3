# Go2 Trot 步态奖励严格模式分析

## 背景

### 修改前的问题

`trot_gait` 函数原本采用宽松模式：每只脚独立判断是否匹配相位，按 4 只脚的正确比例给分（0–1 的连续值）。这降低了学习门槛，但步态跟随效果下降——策略只需要 3/4 正确就能拿到 0.75 的奖励，缺乏压力去形成精确的对角足同步。

### 修改方案

为 `trot_gait` 添加 `strict_mode` 参数，按阶段切换：

| 阶段 | 模式 | 奖励逻辑 |
|------|------|----------|
| Stage1 | `strict_mode=False`（宽松） | 每足独立判断，4 足正确比例（0–1 连续） |
| Stage2 | `strict_mode=True`（严格） | 对角同步 + 相位匹配，全部满足才给 1，否则 0 |
| Stage3 | `strict_mode=True`（严格） | 同 Stage2 |

---

## 两种模式的数学定义

### 宽松模式（Stage1）

```
body order: [FL=0, FR=1, RL=2, RR=3]
stance[0] = phase < 0.5  → FL, RR 应着地
stance[1] = phase > 0.5  → FR, RL 应着地

correct_count = (FL == stance[0]) + (FR == stance[1]) + (RR == stance[0]) + (RL == stance[1])
reward = correct_count / 4.0  → [0.0, 0.25, 0.5, 0.75, 1.0]
```

### 严格模式（Stage2/3）

```
body order: [FL=0, FR=1, RL=2, RR=3]

条件1: FL == RR          (对角足1同步)
条件2: FR == RL          (对角足2同步)
条件3: FL == stance[0]   (对角足1匹配相位)
条件4: FR == stance[1]   (对角足2匹配相位)

reward = (条件1 & 条件2 & 条件3 & 条件4) ? 1.0 : 0.0
```

## 合理性分析

### 优点

**1. 课程递进，学习曲线合理**

Stage1 的宽松信号（连续梯度）让策略快速发现 trot 的大致模式——即使只做到 50% 正确也有正向反馈。Stage2/3 切换为严格二元信号，强迫策略把"大致 trot"精化为"精确 trot"。

这在强化学习中是一个经典技巧：先用 dense reward 引导探索（exploration），再用 sparse reward 精确塑形（refinement）。

**2. Stage2/3 需要精确步态的原因**

- **质量增加**：Stage2 引入 Orin NX + Mid360 负载（总质量从 ~15kg → ~17.6kg），惯性增大。不精确的步态在轻量机体上还能凑合，在重载下会导致能量浪费和失稳。
- **硬件准备**：mid360 头部重量使质心前移，对角足同步不良会导致 pitch 震荡，影响深度传感器数据质量。
- **Stage3 蒸馏**：学生网络（带噪声本体感知 + 10Hz 深度图）的信息带宽低于教师，精确的步态先验可以弥补感知精度损失。

**3. 二元奖励有助于 sharpening**

连续奖励（0–1）的梯度在接近最优解时变得平坦——从 0.75 到 1.0 的改善只带来 0.25 的增量奖励。二元奖励的梯度更陡峭：从不满足到满足是 0→1 的跳跃，迫使策略在步态时序上做出明确承诺（commit），而不是"模糊地接近"。

**4. Stage1 保留宽松模式保护早期探索**

如果从一开始就用严格模式，策略在学会站立之前就面临稀疏的 gait reward——很可能永远无法发现 trot 模式。Stage1 用宽松模式积累步态先验是正确选择。

### 潜在风险

**1. 奖励幅值断崖**

宽松模式下，一个"75% 正确"的策略每步得到 ~0.75 的 trot 奖励。切换到严格模式后，同样策略的 trot 奖励骤降至 0。这可能导致：

- 价值函数估计失准（value function 崩溃）
- 策略在过渡初期出现行为退化

**缓解建议**：
- 监控 Stage1→Stage2 过渡时 trot 奖励和总奖励的变化
- 如果退化严重，可考虑在 Stage1 后期逐步提高严格程度（如 `strict_mode` 从 0→1 的渐进调度），或暂时不切换到严格模式
- 也可以考虑混合奖励：`reward = 0.3 * relaxed + 0.7 * strict` 作为过渡

**2. 二元奖励导致探索不足**

严格模式下，只有精确满足 4 个条件才给奖励。策略可能收敛到次优解（如完全不用 trot，靠其他奖励项驱动行走），因为 trot 的梯度信息太稀疏。

**缓解**：`feet_swing`（+2.0）和 `feet_air_time`（+0.3）提供了辅助的步态相关梯度，即使 trot 严格模式暂时给 0 分，策略仍有信号优化足端运动。

**3. 与现有奖励的交互**

Stage2/3 同时修改了以下奖励：

| 奖励项 | vs Stage1 | 方向 |
|--------|-----------|------|
| `feet_slide` | -0.15 → -0.075 | 放宽 |
| `feet_stumble` | -0.5 → -0.05 | 放宽 |
| `trot_gait` | 宽松 → 严格 | **收紧** |

放宽足端惩罚 + 收紧步态要求，形成了"动作可以更自由，但时序必须更精确"的约束组合。这在物理上是合理的——重载足端冲击大是预期行为，但时序不精确会导致更大的效率损失。

## 综合评估

| 维度 | 评价 |
|------|------|
| 课程递进 | ✅ 合理：宽松→严格符合探索→精化范式 |
| 物理一致性 | ✅ Stage2/3 重载需精确步态，Stage1 轻载可容忍模糊 |
| 向后兼容 | ✅ 默认 `strict_mode=False`，其他配置文件不受影响 |
| 主要风险 | ⚠️ 切换时奖励断崖，需监控并考虑渐进过渡 |

## 代码改动摘要

**`rewards.py`**：`trot_gait()` 新增 `strict_mode: bool = False` 参数。True 时使用对角同步 + 相位匹配的二元判断；False 时保持原每足独立判断。

**`go2_loco_skill_walk_mid360_depth_10hz_cfg.py`**：
- Base `RewardsCfg.trot_gait`：`strict_mode=False`（默认，Stage1 宽松）
- `feet_contact_force`：weight -0.04→**-0.005**，threshold 180→**150**
- `_apply_stage2_config`：覆盖 `trot_gait` 为 `strict_mode=True`
- `_apply_stage3_config`：覆盖 `trot_gait` 为 `strict_mode=True`
